# Отчёт по заданию «TSDB Victoria Metrics и экспорт метрик»

«Кулинарная книга» — Spring Boot 4.1.1 + Thymeleaf, PostgreSQL 16, minikube.
Приложение и PostgreSQL развёрнуты в namespace `cookbook`, VictoriaMetrics — в `monitoring`.

## Стек и схема

| Компонент | Роль |
|---|---|
| Spring Boot Actuator + Micrometer | runtime- и бизнес-метрики приложения |
| `micrometer-registry-prometheus` | OpenMetrics-формат |
| PostgreSQL 16 | БД приложения |
| `postgres-exporter` | метрики PostgreSQL |
| VictoriaMetrics Single | TSDB и scrape |
| Helm | установка VictoriaMetrics |

```text
app:8081/actuator/prometheus ─┐
                              ├── scrape ── VictoriaMetrics (monitoring)
db:9187/metrics ──────────────┘

app → db:5432 (JDBC)
db pod: PostgreSQL :5432 ← postgres-exporter :9187
```

## Экспортёры

- **Приложение:** Actuator на отдельном management-порту `8081`, endpoint
  `/actuator/prometheus`. Runtime-метрики: `jvm_*`, `http_server_requests_*`,
  `hikaricp_*`, `process_*`.
- **PostgreSQL:** sidecar `postgres-exporter` в поде `db`, endpoint
  `9187/metrics`. Подключается к Postgres через `localhost:5432`, логин/пароль
  берёт из `db-secret`.
- **VictoriaMetrics:** Helm-чарт `vm/victoria-metrics-single`, release
  `vm-single` в namespace `monitoring`. Включён `server.scrape.enabled: true`;
  отдельный vmagent не используется — сервер сам скрейпит targets.

## Бизнес-метрики

| Метрика | Prometheus-имя | Где инкрементируется |
|---|---|---|
| Регистрации | `cookbook_users_registered_total` | `UserService.register` |
| Успешные входы | `cookbook_auth_logins_total{result="success"}` | `SecurityEventListener` |
| Неудачные входы | `cookbook_auth_logins_total{result="failure"}` | `SecurityEventListener` |
| Создание рецепта | `cookbook_recipes_total` | `RecipeService.create` |
| Обновление рецепта | `cookbook_recipes_updated_total` | `RecipeService.update` |
| Удаление рецепта | `cookbook_recipes_deleted_total` | `RecipeService.delete` |
| Создание ингредиента | `cookbook_ingredients_total` | `IngredientService.create` |
| Удаление ингредиента | `cookbook_ingredients_deleted_total` | `IngredientService.delete` |

Для `created` Prometheus-клиент нормализует суффикс, поэтому счётчики создания
называются `cookbook_recipes_total` и `cookbook_ingredients_total`.

## Service discovery

Аннотации на pod template:

```yaml
# app
prometheus.io/scrape: "true"
prometheus.io/port: "8081"
prometheus.io/path: "/actuator/prometheus"

# db
prometheus.io/scrape: "true"
prometheus.io/port: "9187"
prometheus.io/path: "/metrics"
```

VictoriaMetrics использует job `kubernetes-pods` и находит оба пода по этим
аннотациям. Дополнительные Service для метрик не создавались.

## Проверка

```bash
kubectl port-forward svc/vm-single-victoria-metrics-single-server \
  -n monitoring 8428:8428
```

```text
http://localhost:8428/targets
http://localhost:8428/api/v1/label/__name__/values
http://localhost:8428/api/v1/query?query=up
http://localhost:8428/vmui/
```

Проверено: `/targets` содержит job `kubernetes-pods` с двумя targets из
namespace `cookbook` в состоянии `up`; `up{namespace="cookbook"}` возвращает `1`;
`pg_up` возвращает `1`; в vmui доступны `cookbook_*`, `jvm_*` и `pg_*`.

Сырые endpoints:

```text
http://localhost:8081/actuator/prometheus
http://localhost:9187/metrics
```
