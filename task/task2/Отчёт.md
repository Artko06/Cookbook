# Отчёт по заданию «Запуск приложения в minikube»

## Приложение

«Кулинарная книга» — клиент-серверное веб-приложение (Spring Boot 4 + Thymeleaf,
данные в PostgreSQL 16). В minikube разворачиваются два сервиса:

- **`app`** — приложение (образ `cookbook-app:latest`, собран из `Dockerfile`);
- **`db`** — база данных (образ `postgres:16-alpine`).

Манифесты лежат в каталоге `k8s/`.

---

## 1. Какие абстракции Kubernetes использованы для запуска

| Kind | Для чего нужен | Почему выбран у нас |
|------|----------------|---------------------|
| `Namespace` | Логически изолировать группу объектов в кластере | Чтобы приложение жило в `cookbook`, не смешиваясь с `kube-system` и другими проектами |
| `ConfigMap` | Хранить несекретную конфигурацию и отдавать её подам как env/файлы | Конфиг приложения через окружение (`DB_URL`, `SERVER_PORT`, профиль, лог) без пересборки образа |
| `Secret` | Хранить секреты (пароли/токены) и передавать их безопасно | Логин/пароль БД — чувствительные данные; передаём в БД и в приложение через `secretRef`/`secretKeyRef` |
| `PersistentVolumeClaim` (PVC) | Запросить диск; кластер создаёт `PersistentVolume` и подключает его | Данные PostgreSQL должны пережить пересоздание пода |
| `Deployment` | Держать нужное число подов, пересоздавать при падении, масштабировать, обновлять | И БД, и приложение — долгоживущие сервисы; задаём `replicas`, пробы, env, `initContainer` |
| `Service` | Стабильный DNS-адрес и балансировка к подам (их IP меняются) | Внутренний `db` (ClusterIP) для `jdbc:postgresql://db:5432`; внешний `app` (NodePort) для доступа к UI |

Соответствие файлов:

| Файл | Объект |
|------|--------|
| `00-namespace.yaml` | `Namespace cookbook` |
| `01-db-pvc.yaml` | `PersistentVolumeClaim db-pvc` |
| `02-db-deployment.yaml` | `Deployment db` |
| `03-db-service.yaml` | `Service db` (ClusterIP) |
| `04-app-configmap.yaml` | `ConfigMap app-config` |
| `05-app-deployment.yaml` | `Deployment app` |
| `06-app-service.yaml` | `Service app` (NodePort) |

`kustomization.yaml` собирает манифесты и генерирует `db-secret` из локального `db-secret.env` (не хранится в git).

## 2. Как сервисы приложения взаимодействуют между собой

- **`app` → `db`:** приложение подключается по `jdbc:postgresql://db:5432/cookbook`.
  Хост `db` — имя `Service` (ClusterIP): Kubernetes резолвит его по DNS и направляет
  трафик на под БД. `DB_URL` берётся из `ConfigMap app-config`, логин/пароль
  (`DB_USER`, `DB_PASSWORD`) — из `Secret db-secret`.
- **Внешний доступ:** пользователь обращается к `Service app` типа `NodePort`
  (порт `30080`) → под `app` (порт `8080`); доступ — `minikube service app -n cookbook`.
- **Порядок запуска:** `initContainer wait-for-db` в `Deployment app` ждёт готовности БД
  (`pg_isready -h db`); приложение стартует только после этого.
- **Данные:** каталог PostgreSQL `/var/lib/postgresql/data` смонтирован из `PVC db-pvc`,
  поэтому данные переживают пересоздание пода.

**Схема:**
```
внешний пользователь → Service app (NodePort:30080) → Pod app
Pod app → Service db (ClusterIP, DNS db:5432) → Pod db → PVC db-pvc
конфигурация: ConfigMap app-config + Secret db-secret → Pod app
```

## 3. Команды демонстрации

```bash
# запуск приложения и зависимостей
# db-secret генерируется kustomize из db-secret.env
kubectl apply -k k8s/spring-boot/

# вывод всех запущенных подов
kubectl get pods -n cookbook

# веб-панель Kubernetes (обзор подов/сервисов/деплойментов)
minikube dashboard

# масштабирование приложения
kubectl scale deploy/app --replicas=2 -n cookbook
kubectl get pods -n cookbook

# доступ к UI
minikube service app -n cookbook
```
